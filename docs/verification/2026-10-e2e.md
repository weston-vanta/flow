A live run of flow against real hosts, following Task 19 of the implementation plan. Host names
are invented: **alpha** is the machine the supervisor ran on, **beta** the second machine used
for workers and the recycle drill, and **gamma** a third running machine that was discovered but
never used. The configured repository is called **app** here, at `/workspaces/app`, with `wt`
worktrees under `/workspaces/app.wt`. Command output is quoted after these substitutions; ids of
the hosts' environments are left out.

flow was at `95fdd48` on alpha and at the commit before it (a docs-only difference) on beta;
herdr 0.9.5 on both; Claude Code 2.1.312. The state directory is shared storage mounted on both
hosts, and so is `~/.claude`.

Nothing was fixed during the run. Where a step could not proceed as written, the operator
stepped in with documented surfaces only (herdr keys into flow's own panes, `flow task orphan`,
`flow task close`, `flow dispatch` with `--dir`), and the record says so.

## Step 2: Start the supervisor

First attempt, from alpha's shell:

```console
$ timeout 90 flow up </dev/null
`herdr --session flow agent wait w1:p1 --until blocked --until idle --until working --timeout 60000` on alpha exited 1: {"error":{"code":"agent_not_found","message":"agent target w1:p1 not found"},"id":"cli:agent:wait"}
exit=1
```

It failed within a second. The workspace (`w1`, label `flow-supervisor`) and the lock were left
in place, and Claude Code did start in the pane, but it sat on the folder-trust dialog for
`/workspaces/flow`, because the handshake that would have accepted it had already bailed. A
second `flow up` attached (no second workspace) and ended with herdr's `Not a tty` error. The
operator accepted the dialog with `herdr pane send-keys --session flow w1:p1 down enter`.

The supervisor's first turn then showed:

```
SessionStart:startup hook error
Failed with non-blocking status code: state directory not found: /tmp/flow-verify.WOcp/state (expected a symlink to /efs-home/flow/state)
…
Stop hook error: Failed with non-blocking status code: state directory not found: /tmp/flow-verify.WOcp/state …
```

The herdr server for session `flow` on alpha had been started earlier by a verification run with
`FLOW_STATE=/tmp/flow-verify.WOcp/state` in its environment (seen in `/proc/<pid>/environ`), and
every pane inherits it. The SessionStart and Stop hooks all failed, and `claude_session` in the
lock stayed `null`. The supervisor noticed and worked around it for its own commands only.

Recovery: `herdr workspace close --session flow w1`, `herdr --session flow server stop`, then
`flow up` again. It failed the same way (`agent_not_found` on `w1:p1`), but this time the
directory was already trusted, so the supervisor came up on its own. The SessionStart hook
recorded the session in `state/supervisor/lock.json`.

```console
$ flow status
no open tasks
adopted: 6 sessions
$ flow sessions
beta   w1:p1  idle     adopted  <hand session title>  <summary A>
```

The supervisor is listed as adopted, as the step expects. Every hand session shows the same
summary (Finding 7), and alpha `w1:p1` appears twice because the user's default herdr session
also has a `w1:p1` (Finding 8). Running `flow up` again with the supervisor live attached
instead of starting a second supervisor (`Error: Os { code: 25, kind: Uncategorized, message:
"Not a tty" }`, one workspace).

**PARTIAL:** status and sessions are as expected, but `flow up` exits 1 on every start, the trust
dialog needs a human, and a leaked `FLOW_STATE` silently disables every hook.

## Step 6: Recycle drill

`herdr workspace close --session flow w1` on alpha. Between the stop and the restart, a task was
dispatched to beta (`2sqvuhil`, "e2e between") and finished.

From beta (`ONA_ID` is unset in ssh shells, so it was passed by hand on the second try):

```console
beta$ cd /workspaces/flow && timeout 20 flow up </dev/null

```

beta has no ssh aliases for the other environments, and its Ona CLI is logged in as the
environment's own principal, which sees only beta, so `gitpod environment ssh-config` cannot
provide them. The operator's login is not available there. A supervisor started on beta could not

The drill was then run on alpha itself, to exercise `--resume`:

```console
alpha$ timeout 90 flow up </dev/null
`herdr --session flow agent wait w4:p1 …` on alpha exited 1: {"error":{"code":"agent_not_found",…}}

`herdr --session flow agent wait w5:p1 …` on alpha exited 1: {"error":{"code":"agent_not_found",…}}
```

Claude Code was launched with `--resume`, but the handshake failed before it could start, so
flow closed that workspace, cleared `claude_session` in the lock, and started a fresh session.
The old transcript was never touched. A repeat (close, `flow up`) did exactly the same. So the
supervisor never resumes its conversation.

The fresh supervisor's session start ran `flow wake drain` (empty: nothing queues wakes while no
watcher runs) and `flow status`, and noticed `2sqvuhil` finished but unclosed. At its stop the
watcher woke `done: 2sqvuhil`, and it closed the task. The fresh session tried `ssh beta …` to
check the file, which failed (Finding 12).

**FAIL:** no cross-host move, and no resume even on the same host. What happened in between did

## Findings

1. **The start handshake fails with `agent_not_found`, deterministically.** `await_start` calls
   `herdr agent wait` right after `herdr pane run`, before herdr has detected an agent in the pane.
   Claude Code took about 1 to 20 s to appear (beta's pane shell starts slowly). Every `flow up`
   and every `flow dispatch` in this run (11 of 11) exited 1, and three things follow. Dispatched
   tasks start `blocked` with a supervisor hold, the trust dialog is never accepted, and
   `flow up` treats a good `--resume` as failed (Finding 2). Evidence: Steps 2, 3, 5 and 6. Fix:
   treat `agent_not_found` as "not yet" and retry until the start timeout runs out (or wait first
   for `pane wait-output`/process info), or start with `herdr agent start`, which returns once the
   agent is ready.
2. **`flow up` throws away the supervisor's conversation on every restart.** Because of Finding 1,
   the resume retry path closes the resumed workspace, sets `claude_session` to null and starts
   fresh. It did this on both recycles, so `--resume` never takes effect. Fix: Finding 1. Also
   drop the session only when the failure shows that Claude could not find it (for example a
   "No conversation found" in the pane), not on any handshake error.
3. **The worktree path includes `wt`'s status note.** `wt create <branch>` ends with
   `<path>  (new branch <branch>, 109.6s)`, and `create_with_tool` takes the last line whole. The
   task's cwd, its brief and the pane's directory are then wrong; herdr falls back to `$HOME`.
   Fix: have `flow init` write `["wt", "--json", "create", "{branch}"]` and parse the path from
   JSON, or take the first whitespace-delimited token of the line and check that the directory
   exists on the host before using it.
4. **`flow guard` blocks a stop whose watcher has just woken.** On the first stop with an
   actionable task, the async `flow watch` took the lock, found `blocked: <id>`, queued the wake
   and exited within the guard's 5 s grace window. The guard then saw no live watcher and
   blocked, and it does not re-check the queue. The supervisor got both the wake and the
   guard's "no watcher" message, and started a background `flow watch` of its own. Fix: in the
   grace loop, also stop waiting when the wake queue becomes non-empty, and let the pending wake
   carry the turn. Optionally have the watcher write a "woke" marker that the guard accepts.
5. **Watchers started by hand in a background shell cost extra turns.** Each exit of a background
   `flow watch` (0 for "nothing to watch", 2 for a wake) comes back as a "Background command …
   completed/failed" notification, which starts a supervisor turn. One orphan made three turns.
   Fix: with Finding 4 fixed, the guard rarely needs to say this. Its message could also say to
   end the turn so the hook watcher re-arms.
6. **A `FLOW_STATE` left in the herdr server's environment silently breaks the supervisor.**
   herdr's `flow` session server keeps the environment of whoever started it first. A
   verification run had left `FLOW_STATE` pointing at a deleted temporary directory, so every
   hook in every pane failed (non-blocking), and no session was recorded or watched. Fix: have
   `flow up` and `flow dispatch` pass the state path explicitly (`env FLOW_STATE=<path> claude …`
   in the launch line, or `--settings` with the path), or refuse to start when the server's
   `FLOW_STATE` differs from the caller's. At least, make `flow guard` failing on a missing state
   directory a blocking error in the supervisor.
7. **Adopted sessions get the wrong Claude session and summary.** Every hand session in
   `/workspaces/app`, on every host, matched the same registry session, the newest one in that
   cwd (`match_agents` never claims a session it has given to one agent, and the registry is
   shared across hosts). All rows showed the same summary. This is wider than the documented
   limitation, which mentions only sibling machines. herdr already reports each agent's Claude
   session id (`agent_session.value`, source `herdr:claude`) in `agent list` and `agent wait`.
   Fix: match on that id first, and fall back to cwd only when herdr has none.
8. **Pane ids collide across herdr sessions in `flow sessions`.** alpha `w1:p1` appears twice
   (the supervisor in session `flow` and a hand session in `default`). The JSON has a `session`
   field, but the text view does not show it. Fix: show the herdr session (or `flow:`/`default:`
   prefixes) when it is not `flow`.
9. **`flow status`'s adopted count is not `flow sessions`' row count.** `status` counts from the
   cached inventory (7, then 8, including the supervisor and closed task panes), while
   `sessions` lists live agents (6). The supervisor commented on this twice. Fix: count from the
   same source, or label the number as cached with its age.
10. **Remote `herdr agent wait` processes outlive their watcher.** With ssh multiplexing, killing
    the local ssh client does not end the remote command. Waits pile up for up to an hour, even
    on closed panes (Step 7). Fix: run remote waits under a wrapper that exits when stdin closes
    (`sh -c 'herdr … & p=$!; cat >/dev/null; kill $p'`), or use a shorter `--timeout` that the
    watcher renews.
11. **Only the operator's machine can host the supervisor.** beta has no ssh aliases for the
    other environments, and its Ona CLI is the environment's own principal, so `flow up` there
    refuses ("supervisor host … unreachable"). The README asks for the Ona login "on the
    supervisor's machine", which does not cover moving the supervisor. Fix: document that every
    host that may run the supervisor needs the operator's Ona login and `ssh-config`. Have
    `flow up` say that when the alias does not resolve, rather than suggesting removing the lock,
    which would also lose the session to resume.
12. **The fresh supervisor tried `ssh <host>` to check a worker's file.** The flow-wake skill
    tells it to check the report against the criteria but not how to look at another host. One
    session used `flow host run`, one used `ssh beta` and failed. Fix: name `flow host run <host>
    -- <argv>` in the flow-wake skill's `done` step.
13. **A worker's `done` with no watcher running waits for the supervisor's next stop.** Tasks
    dispatched outside a supervisor turn (by the operator's shell) finished with nothing
    watching. The wake came only when the supervisor next ended a turn. This is by design, but
    `flow dispatch` run by hand gives no hint of it. Fix: after a dispatch from outside the
    supervisor, have `flow dispatch` print that the supervisor will hear of it at its next turn,
    or nudge the supervisor.
14. **Smaller items.** `flow task decide` on a dispatch-failure hold leaves the task `blocked`
    (only `steer` sets `working`), which the supervisor called "probably left over". `flow task
    orphan` prints nothing on success. `flow init` prints the whole inventory of every host
    (dozens of lines) before its summary.
