# Simplicity

**Asks:** could the same behaviour take half the code? Does each edge case's risk justify its complexity? Would a product tradeoff simplify it?

**A finding must show:** a sketched alternative with its rough size against the current one, or the product tradeoff it needs (what behaviour gives way, and what that saves).

Code that handles a case unlikely to happen and cheap when it does is a finding; name the case and what removing it saves.
